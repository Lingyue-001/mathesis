# 01 成果范围：把人工判断变成编译输入

## 1. 可交付功能
本轮交付一个本地“专家辅助编译工作台”，复用 v3.1 的语义图、过程定义、端口链接和精确执行。人工对切分、角色、受事、来源、控制范围、率或解释方案作结构化判断；编译器兑现这些判断并检查依赖。

最终至少交出：
1. 可操作的本地界面，支持原文定位、候选选择、受限自由切分、已知类型结构填表、保存/撤销和重算。
2. 持久化且可重放的审定账；包含决策人类别、原始自动候选、人工新增部分、证据和影响范围。
3. `ReviewedProcedureBundle`：源文、编辑来源、AST/过程定义、量/操作/端口图、外部依赖、解释方案、审定状态、执行记录。
4. 至少两个完整目标的审定图和一个新图再导入演示；两图可并置查看共同结构和差异，并逐项点回原文。
5. 区分自动发现、候选选择、人工构造、资料补充和新语义开发的成本报告。

## 2. 人工判断的四种工作，不得混记
- `candidate_selection`：正确选项已在原候选集合里，研究者选择或拒绝。
- `typed_manual_construction`：原候选没有正确结构，研究者圈选原文，选已有操作类型并填操作对象、条件、返回口。
- `evidence_completion`：补入有来源的参数、表、背景过程或解释方案；应由正文计算的中间值不得以此填入。
- `ontology_extension_request`：现有操作语义无法表示，登记待开发。当前目标保留部分图或未知节点，不能假定已完整。

选择候选与人工构造都属于合法辅助模式。前者比例必须实测，不能事前宣称绝大多数都能二选一。人工构造允许组合有限类型，可能涉及较多判断；界面必须如实记录。

## 3. 本轮完成层级
分别报告：
- `review_status`：draft / in_review / approved / needs_revalidation。
- `graph_status`：partial / invalid / closed。closed允许有已明确类型与来源的合法符号根输入；不允许悬空的派生量。
- `execution_status`：not_requested / missing_inputs / unsupported / failed / executed。
- `comparison_status`：blocked / scoped_ready / ready；列出可比维度与未闭合维度。

`approved`不自动推出closed；closed不自动推出有数值执行；某个数值执行成功也不能自动推出全图史学解释正确。
完整目标必须覆盖其必要步骤、控制与上游依赖。未匹配跨度、未知primitive和未证实的必要控制不可仅靠“接受”按钮消除。
存在互斥学者解释时保存两个分析分支；每个分支单独审定和检查。不要把不同解释的边混入一张宣称唯一成立的图。

## 4. 比较的有限落点
核心硬终点是可回放、统一契约下的审定图。并置比较演示必须包含：输入/输出角色、操作端口、依赖路径、单位/尺度、起点、控制范围、解释方案及原词。

本轮可先由研究者指定一个任务或阶段对应，程序据此列出两图已记录的相同属性和差异。这个对应本身标为人工比较决策，不回填解析候选。禁止宣称已实现全语料自动匹配、最优图编辑距离或自动历史创新判断。

现有README提到的旧比较器只能在实际检查schema适配后复用。不能把旧匹配分数当作新IR的经过验证的历史比较。

## 5. 不在本轮承担
自动校勘、自动发现全部缺失背景、任意古汉语理解、全体43个拒绝程序的完整复原、跨传统通用本体、在线多用户权限系统、生产网站发布。可记录需求，不能以这些长期目标推迟工作台的实际交付。
