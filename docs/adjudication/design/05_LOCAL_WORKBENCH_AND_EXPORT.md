# 05 必须交付的本地工作台

## 1. 最小可用界面
一个页面即可，职责明确：
- 原文区：只读正文、版本、编辑标记、层级边界；可拖选字符并高亮多个证据跨度。
- 审定区：当前问题、原因、受影响输出、候选与出处；“选择”“手动划分”“用已有类型构造”“补背景”“保留未决”。
- 结构区：过程/阶段树、操作和端口表、图预览、未闭合依赖。图是产物，不要求研究者直接拖边画算法。
- 操作区：保存/撤销/重做、重新编译、查看变化、核验、在根输入充分时执行、按范围签署、导出。

不能只交一套让研究者手写JSON的命令行功能。CLI用于自动回放和测试，实际研究入口必须可点选、可圈文、可填结构槽。

## 2. “选择ontology”的UI翻译
用户看到的应是“操作类型/数量类型/解释方案”，例如条件、相加、表格定位、依次消去、按表递推。不要让用户在整套本体文件之间猜选。

选择一种操作后，表单由其签名生成：输入量、接收量、条件、body、表、边界、返回口。每项显示可引用的已知对象与source位置；缺对象可先标一个source mention再链接。

没有正确选项时可以组合目录内节点。目录之外的选项进入扩展请求；普通界面不会产生自定义opcode。

## 3. 保存与回放
- 保存在独立session目录；源文及旧结果只读。
- 关闭服务/浏览器再打开，source+decisions可重建同一语义图；trace含运行身份，规范化图hash不依赖时间戳或临时ID。
- 文件导入校验source/hash/目录版本；冲突展示差异，不自动合并相互矛盾判断。
- 从局部确认追踪其影响的下游步骤，提供跳转；减少连续问同一根因造成的重复工作。

## 4. 导出
`ReviewedProcedureBundle`至少保存source packet、profiles、decision log、syntax/program views、event/value graph、dependency/port checks、completeness map、可选执行trace、ontology/engine版本及文件hash。

同时提供节点/边CSV作为派生视图，不能用CSV丢掉scope、控制和证据后称其等价于完整bundle。图可用JSON或GraphML适配导入其他工具；本轮以完整JSON为规范。

## 5. 双图演示
选择已审定的两个对应目标或阶段；对照原文、角色、输入输出、参数、单位/尺度、起点、条件、循环和依赖。
允许研究者手工声明阶段对应，系统检查两边对应节点的字段、端口与子图并生成差异清单。明确输出“人工对齐＋程序检查”，不得伪报自动发现对应。

不完整图可以并置浏览，但未解析部分显示unknown。只有确认完整的对应范围，才允许把某节点不出现描述为absence；不可把无解析当成历史删步。

## 6. 部署与安全
优先复用工作区已有UI样式与JS工具。当前结果ZIP没有完整网站源码，Work要在其原工作区核对实际资源。
本轮开发独立本地路由/页面与Python适配，不改线上导航、全站风格或canonical data。服务默认127.0.0.1；不接受任意shell/eval；上传路径及session文件访问受限；原文用textContent渲染。
Windows环境仍需实际启动和文件路径检查；无对应环境时如实报告已测环境，不宣称跨平台全验。
