# Adjudication requirements traceability matrix

本表在 M2 前建立。01–06 的每个正文段落、清单项与表行均保留原文定位；H01–H46 单独映射；X01–X13 补充用户约束与契约入口。

M2 core 的实际 test ID 与运行证据见 [m2-evidence.md](m2-evidence.md)；M3 UI、M4 primitive/comparison 仍是待实施项。拟定 test 路径/ID 可以合并，但必须保留 requirement ID → 实际 test ID → 运行证据关系；不得因重构删掉规格。H46 的自动模式和 M2 review-mode 回归均见该证据表。

`requirements.json` 是本表机器可读版本；Markdown 是可读视图。`design/provenance.json` 锁定原文。正文中简称 `operations.py/execution.py/scoped.py` 等均指 `analysis_parser/` 内模块。

设计包 07 的文件名/任务顺序是建议：按 [repository 架构](../architecture.md) 映射到独立 `adjudication/`、`workbench/`、`comparison/`；用户的 M1→M2→M3→M4 顺序优先。08/09、WORK_START_HERE 与 evidence 是既有基线/验证说明，不是新增功能已实现证明；原包由 provenance hash 引用。

发现的契约缺口：原 envelope 没有 reject_candidate、definition_anchor；M2 应在独立版本契约中补齐并写反例，不改原设计证据。defer 的 payload 必须区分 unresolved 和 schema_extension_required。原 schema 的 start/end 关系、quote/hash、依赖环、payload typed slots 需要语义 validator，不能只靠 JSON schema。
